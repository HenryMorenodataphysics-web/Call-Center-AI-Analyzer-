# Analytical Contract v1

## Purpose

This contract defines what every analytical dataset and core metric means in
AI Analyzer Core. It prevents observed signals, heuristic proxies, and real
business outcomes from being mixed or presented as equivalent.

The machine-readable source of truth is
`config/analytical_contract_v1.json`. The current contract version is `1.0.0`.

## Analytical layers

### Observed and extracted signals

These fields describe what the pipeline directly extracted or detected:

- ASR text and timestamps.
- Text sentiment label and classifier score.
- RMS energy, RMS dB, pitch, spectral centroid, and speaking rate.
- Within-call volume, pitch, speaking-rate, and vocal-intensity levels.
- Rule-based frustration, empathy, probing, ownership, and next-step flags.
- Audio call duration.

These signals can support an explanation, but none is a customer outcome by
itself.

### Derived proxies

The following fields are analytical aids, not official business metrics:

- `turn_risk_score`
- `conversation_risk_score`
- `heuristic_quality_proxy = 100 - conversation_risk_score`
- `needs_manual_review`
- `agent_rank_by_heuristic_risk`
- `estimated_aht_sec`

The risk score is generated by `conversation_risk_v1`. It is an uncalibrated
heuristic rubric. It is not a probability, QA score, CSAT score, survey
prediction, or official performance rating.

`agent_rank_by_heuristic_risk` is a descriptive ordering for portfolio
exploration. It is not adjusted for call mix, call complexity, language,
market, or sample size and must not be used for management decisions.

### Real outcomes

The current AppTek portfolio dataset does not provide:

- Official AHT
- CSAT
- NPS
- QA score
- Five Stars
- Call-level survey result

These fields remain `not_available` in the metric catalog. Synthetic values may
be introduced later for a clearly labeled dashboard demonstration, but they
must remain separate from analyzed call outputs.

## Data grains and keys

| Entity | Grain | Primary key | Canonical location |
|---|---|---|---|
| Call registry | One row per call | `call_id` | `data/metadata/calls_metadata.csv` |
| Transcript | One ASR segment per call/channel | `call_id, channel, segment_id` | `data/transcripts/` |
| Speaker turn | One normalized speaker turn | `call_id, turn_id` | `data/speaker_turns/` |
| Text analysis | One text analysis per turn | `call_id, turn_id` | `data/text_analysis/` |
| Acoustic analysis | One acoustic analysis per turn | `call_id, turn_id` | `data/acoustic_features/` |
| Fused call turn | One fused analytical row per turn | `call_id, turn_id` | `data/final_outputs/*_turn_fusion.csv` |
| Call summary | One analytical row per call | `call_id` | `data/final_outputs/*_call_summary.csv` |
| All calls | One analytical row per call | `call_id` | `data/final_outputs/all_calls_summary.csv` |
| Agent summary | One portfolio-period row per agent | `agent_id` | `data/dashboard_data/agent_dashboard_summary.csv` |

Per-call summaries are canonical. Batch range files such as
`calls_summary_Agent_001_to_Agent_001.csv` are execution artifacts and are not
dashboard sources.

## Confidence

`signal_coverage_confidence` measures whether the inputs needed by the analysis
are available. It does not measure whether the model prediction is correct.

The turn-level coverage formula is:

- Non-empty text: 0.20
- Usable normalized sentiment and classifier score: 0.30
- RMS dB, speaking rate, and pitch availability: 0.50 shared equally

Call-level confidence is the mean turn coverage. Agent-level confidence reports
the mean and minimum across the agent's calls.

No field is currently named `risk_probability` or `survey_probability` because
there are no real labels with which to calibrate those probabilities.

## Evidence and reason codes

Free-text explanations remain available in `turn_main_signal` and
`main_reasons`, but stable reason codes are the integration contract for future
dashboards and the LLM.

| Reason code | Meaning | Evidence |
|---|---|---|
| `CUST_NEGATIVE_SENTIMENT` | Negative customer text sentiment | Matching customer `turn_id` values |
| `CUST_FRUSTRATION_LANGUAGE` | Configured frustration phrase | Matching customer `turn_id` values |
| `CUST_HIGH_VOCAL_INTENSITY` | High within-call vocal intensity | Matching customer `turn_id` values |
| `AGENT_EMPATHY` | Configured empathy phrase | Matching agent `turn_id` values |
| `AGENT_PROBING` | Probing question detected | Matching agent `turn_id` values |
| `AGENT_OWNERSHIP` | Configured ownership phrase | Matching agent `turn_id` values |
| `AGENT_NEXT_STEPS` | Configured next-step phrase | Matching agent `turn_id` values |
| `AGENT_NO_PROBING` | No probing detected in the call | Call-level absence rule |
| `AGENT_NO_OWNERSHIP` | No ownership phrase detected | Call-level absence rule |
| `AGENT_NO_NEXT_STEPS` | No next-step phrase detected | Call-level absence rule |

Every turn receives an `evidence_id` such as
`en_AU_Agriculture_1586330:turn:4`. Each call summary contains `evidence_json`,
which maps reason codes to supporting turn IDs. Absence rules use an empty list
because their evidence is evaluated over the entire call.

## Risk rubric review

Contract v1 preserves the existing weights and thresholds so historical
results do not change silently.

- Low: 0-29
- Medium: 30-59
- High: 60-100

Observed on the 100-call portfolio sample:

- Minimum score: 0
- Maximum score: 47
- Low: 76 calls
- Medium: 24 calls
- High: 0 calls

This distribution is evidence that the rubric has not yet been calibrated, not
evidence that the dataset contains no difficult calls. Reweighting or changing
thresholds requires real outcomes or a reviewed human-label set and must create
a new rubric version.

## Versioning rules

- Adding optional descriptive metadata may produce a minor contract version.
- Renaming fields, changing keys, changing metric meaning, or changing scoring
  weights requires a new contract or rubric version.
- Historical outputs must retain the version under which they were created.
- A score must never change while keeping the same rubric version.
